# T108: Unified versioning for apps and packages

## Goal

Establish a single, consistent versioning scheme across all published packages (NuGet/NPM) and all Unity apps. Currently packages have automated versioning via content hashing; apps have no versioning at all (static values, `bundleVersionCode` hardcoded to 1).

## Context

### Current state

**Packages** (automated, working):
- `build/package-versions.json` tracks version + content hash per package
- `publish_packages.py` computes content hash, compares to stored hash, auto-increments patch if changed
- Publishes to NuGet (api-client) and NPM (core, arfoundation, magicleap)
- Versions committed back to repo via `commit_artifacts.py`

**Apps** (no automation):
- `bundleVersion` is static in each `ProjectSettings.asset` (e.g. `0.1.0`)
- `AndroidBundleVersionCode` is hardcoded to `1` in all projects (must monotonically increase for Play Store)
- Only `Outernet.Client` appends commit SHA to bundleVersion at build time via `BuildInfo.generated.cs`
- `AndroidMobile` and `MapRegistrationTool` have no version manipulation at all

**`BuildInfo.generated.cs`** (should be eliminated):
- Generated by `build_unity.py` during CI, only for projects that have an `Assets/OuternetClient/` directory
- Contains `public const string CommitSha` (first 8 chars of git SHA)
- Used by `AppSetup.cs` to log the commit SHA on startup
- Used by `BuildScript.cs` to append SHA to `bundleVersion`
- With run-number-based versioning, the commit SHA becomes redundant for traceability — the run number links directly to the CI run which has the SHA

## Design decisions

All decisions below were made during discussion in the session that created this ticket.

### Versioning scheme: SemVer with manual major.minor, auto patch

- **SemVer** for both apps and packages: `{major}.{minor}.{patch}`
- **Manual major.minor**: bumped by editing the state file directly when a release milestone warrants it
- **Auto patch**: incremented automatically when content hash changes (same mechanism packages already use)
- **Build metadata**: run number appended as `+{run_number}` (e.g. `0.2.3+14832`). Provides CI traceability without affecting semantic version comparison
- **Branch handling**: non-main builds get pre-release suffix: `0.2.3-dev+14832`
- **`bundleVersionCode`** (Android integer for Play Store): use GitHub Actions `run_number` directly. Monotonically increasing, unique, zero state management

### Content hashing

- **Same mechanism everywhere**: content hash decides whether to bump the version, for both apps and packages
- **App hash scope includes dependencies**: app hash = hash of app directory contents + hash of package content hashes. If a Placeframe SDK package changes, the app hash changes even if app code didn't. Use package *content hashes* (not version strings) as input — version strings only bump on main, but content hashes are always fresh
- **One entry per app in state file**, not per target. Outernet.Client is one entry because the content hash is identical regardless of build target

### State file

- **Rename** `build/package-versions.json` → `build/versions.json`
- **Add `apps` section** alongside existing `packages` section:
  ```json
  {
    "packages": {
      "api-client": { "version": "0.1.5", "hash": "..." },
      "core": { "version": "1.0.3", "hash": "..." },
      ...
    },
    "apps": {
      "Outernet.Client": { "version": "0.1.0", "hash": "" },
      "AndroidMobile": { "version": "0.1.0", "hash": "" },
      "MapRegistrationTool": { "version": "1.0.0", "hash": "" }
    }
  }
  ```
- Update all references: `.gitattributes`, CI workflow (`paths-ignore` x2, artifact name, artifact path, download name), `commit_artifacts.py`, `publish_packages.py`

### Eliminate `BuildInfo.generated.cs`

- Remove generation from `build_unity.py` (the `build_info_path` block)
- Remove `--commit-sha` parameter from `build_unity.py` and CI workflow
- Replace `BuildInfo.CommitSha` usage in `AppSetup.cs` with `Application.version` (reads `bundleVersion`)
- Remove `PlayerSettings.bundleVersion = $"...{BuildInfo.CommitSha}"` from `BuildScript.cs` (version is now injected by Python)

### Version injection into Unity

- **Python manipulates `ProjectSettings.asset` directly** before launching Unity batchmode
- Set `bundleVersion` field via regex replacement (it's a simple YAML `key: value` line)
- Set `AndroidBundleVersionCode` the same way
- No generated C# files needed
- `build_unity.py` gets new parameters: `--run-number` (from `${{ github.run_number }}`), `--branch` (from `${{ github.head_ref || github.ref_name }}`)
- Reads version from `versions.json`, formats with run number and branch suffix, writes to ProjectSettings

### App version bumping in publish step

- `publish_packages.py` already runs on main only — extend it to also compute app hashes and bump app versions when changed
- App hash = hash of app directory + package content hashes folded in
- Save updated app state to `versions.json` alongside package state

## Files to modify

- `build/src/build_scripts/placeframe/ci/build_unity.py` — remove BuildInfo generation, add version injection into ProjectSettings.asset, replace `--commit-sha` with `--run-number` + `--branch`
- `build/src/build_scripts/placeframe/ci/publish_packages.py` — read from `state["packages"]` instead of top-level, add app hash computation and version bumping, save both to `versions.json`

## Done when

- `versions.json` exists with both packages and apps sections
- Package publishing reads from `state["packages"]` and still works correctly
- App versions auto-increment patch when content changes (including dependency changes)
- `bundleVersion` is injected into `ProjectSettings.asset` as `{version}+{run_number}` (main) or `{version}-dev+{run_number}` (other branches)
- `AndroidBundleVersionCode` is set to `run_number`
- `BuildInfo.generated.cs` no longer exists anywhere in the pipeline
- `AppSetup.cs` logs `Application.version` instead of `BuildInfo.CommitSha`
- All references to `package-versions.json` are updated to `versions.json`
